# Contributing to nightshift

## Commit style

Use [Conventional Commits](https://www.conventionalcommits.org/): `feat(collector): add dry-run flag`, `fix(server): handle empty manifest`.

- Imperative subject line, at most 72 characters.
- Body (optional) explains **why**, not only what changed.
- Plain authorship only: no `Co-Authored-By` trailers, no “generated by” lines, and no tool or model names in the message. Describe the subject matter, not the vendor — prefer `feat(ingest): accept session bundles in jsonl zip` over naming the assistant product. Code identifiers such as `claude_projects_dir` are not matched.

The `commit-msg` hook (see Local setup) enforces these rules on every commit.

## Branch naming

Use `feat/<slug>`, `fix/<slug>`, or `chore/<slug>`.

Do not use `agent/`, `cursor/`, `claude/`, or `ai/` prefixes.

## Pull request text

Write PR descriptions in the owner’s first-person voice (“adds …”, “fixes …”). Include what changed, why, and how it was verified.

No AI attribution, no agent product names, and no emoji-decorated boilerplate.

## Authorship and attribution

Commits should be authored and committed as the owner:

`DasVR <arriqaalraee@gmail.com>`

Run `node scripts/check_authorship.mjs` to scan history and tracked files. It separates **violations** (credit trailers, agent identities, non-owner authors, `generated-by` comments, agent-branded branches) from **advisories** (subject-matter mentions of the tools whose sessions nightshift handles — never fatal). Default mode is report-only. `--strict` exits with a non-zero status when violations are found; use `--strict --range=origin/main..HEAD` before opening a PR.

History is never rewritten. Existing findings are recorded in `docs/AUTHORSHIP-AUDIT.md`.
